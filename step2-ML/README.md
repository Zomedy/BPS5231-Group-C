

\# AI-Assisted Thermal Resilience Assessment of Data Centers Under Extreme Heatwaves



A simulation-informed machine-learning framework for evaluating data-center thermal resilience under synthetic extreme heatwaves in Singapore.



This repository contains EnergyPlus simulation data, Python scripts, trained machine-learning models, independent verification results, and the final research report.



\## 1. Research Overview



Data centers require continuous cooling to maintain reliable IT operation. Extreme heatwaves can increase cooling demand and create thermal risks when cooling capacity becomes insufficient.



This study combines DesignBuilder/EnergyPlus simulations with machine-learning surrogate models to enable rapid thermal-risk assessment without repeatedly running computationally expensive building simulations.



\### Research Objectives



1\. Predict thermal-risk categories under different heatwave and operating conditions.

2\. Estimate the maximum Data Hall zone-mean air temperature (Tmax).

3\. Identify the most influential parameters affecting thermal performance.

4\. Evaluate model reliability near thermal-risk boundaries.

5\. Support rapid scenario screening through an interactive AI prediction application.



\## 2. Simulation Model



The reference data-center model was developed using DesignBuilder and simulated with EnergyPlus 9.4.0.



\- Location: Singapore

\- Weather dataset: Singapore IWEC

\- HVAC representation: Ideal Loads Air System

\- Baseline cooling capacity: 68.089 kW

\- Reference IT load density: 600 W/m2

\- Reference cooling setpoint: 24 degC



Synthetic heatwaves were generated by increasing outdoor dry-bulb temperature in the EPW weather file.



A simplified cooling-capacity derating assumption of 2% per degree Celsius of heatwave intensity was applied.



This derating factor is a study-defined sensitivity assumption rather than a calibrated equipment-performance model.



\## 3. Input Parameters



Five input variables were considered:



| Parameter | Range | Unit |

|---|---|---|

| Heatwave intensity | 0–10 | degC above baseline |

| Heatwave duration | 1–5 | days |

| IT load density | 300–1000 | W/m2 |

| Cooling capacity ratio | 0.90–1.30 | dimensionless |

| Cooling setpoint | 20–27 | degC |



The available cooling capacity was calculated as:



Q\_design = 68.089 × (IT\_Load / 600) kW



Q\_available = Q\_design × Capacity\_Ratio × (1 - 0.02 × Heatwave\_Intensity)



\## 4. Dataset Generation



The research includes:



| Dataset | Number of Cases | Purpose |

|---|---:|---|

| Initial Latin Hypercube Sampling | 500 | Initial model development |

| Development diagnostic cases | 12 | Boundary-focused error investigation |

| Adaptive simulations | 40 | Model improvement |

| Final independent verification | 20 | Frozen-model evaluation |



The augmented training dataset contains 540 simulations.



The 12 diagnostic cases informed adaptive sampling and were not used as the final independent verification set.



\### Thermal Risk Definitions



Three study-defined categories were used:



\- Safe: Tmax < 27 degC

\- Warning: 27 degC <= Tmax < 30 degC

\- Failure: Tmax >= 30 degC



These categories are exploratory screening thresholds and do not represent official server failure limits.



Scenarios with Tmax >= 40 degC were treated as severe thermal-runaway cases and excluded from operational Tmax regression training.



\## 5. Machine Learning



The following approaches were investigated during model development:



\- Logistic and linear regression baselines

\- Random Forest

\- HistGradientBoosting

\- Direct risk classification

\- Regression-derived risk classification



The final prediction framework uses:



\- HistGradientBoostingClassifier for thermal-risk classification

\- HistGradientBoostingRegressor for operational Tmax prediction



Model evaluation included five-fold cross-validation, macro-F1, Failure recall, MAE, RMSE, permutation importance, and SHAP analysis.



\### Adaptive Sampling



Forty additional EnergyPlus simulations were generated:



\- 30 boundary-focused cases

\- 10 supplementary coverage-focused cases



Adaptive sampling improved operational Tmax regression on development diagnostic cases but did not consistently improve three-class classification accuracy.



\## 6. Final Independent Verification



Twenty new EnergyPlus scenarios were generated after model selection:



\- 10 general scenarios

\- 10 boundary-oriented scenarios



The frozen models were evaluated without subsequent retraining or threshold adjustment.



\### Classification Performance



| Metric | Result |

|---|---:|

| Overall accuracy | 85.0% |

| Overall macro-F1 | 0.776 |

| General-case accuracy | 100% |

| Boundary-case accuracy | 70% |

| Failure recall | 100% (2 observed cases) |



\### Temperature Regression Performance



Regression evaluation included 19 cases with simulated Tmax below 40 degC.



| Metric | Result |

|---|---:|

| MAE | 1.009 degC |

| RMSE | 1.279 degC |



The limited number of observed Failure cases means that Failure recall should be interpreted cautiously.

\## 8. Installation



\### Requirements



\- Python 3.10 or later (recommended; exact training version not verified)

\- EnergyPlus 9.4.0 for simulation reproduction

\- Python packages listed in requirements.txt



Install Python dependencies:



```bash

python -m pip install -r requirements.txt

```



\### EnergyPlus Configuration



Simulation scripts currently expect the EnergyPlus executable at:



```text

C:/EnergyPlusV9-4-0/energyplus.exe

```



Update `ENERGYPLUS\_EXE` in the relevant simulation scripts if EnergyPlus is installed elsewhere.



The scripts also require:



```text

SGP\_SINGAPORE\_IWEC.epw

```



Place a legitimately obtained compatible EPW file in the repository root before running EnergyPlus.



The weather file is not included in this repository.



\## 9. Reproducing the Research



The supplied `dataset.csv` contains the initial 500 simulation results.



The original initial-data-generation script is not included in this release. Reproduction therefore starts from the supplied dataset.



\### Stage 6: Adaptive Sampling



```bash

python stage6\_adaptive\_sampling.py

```



This generates 40 new adaptive simulation scenarios.



Run the corresponding EnergyPlus simulations:



```bash

python stage6\_adaptive\_runner.py

```



\### Stage 7: Model Retraining



```bash

python stage7\_retraining.py

```



This compares original and augmented training datasets and saves trained models.



\### Stage 8: Classification Optimization



```bash

python stage8\_classification\_optimization.py

```



This compares direct and regression-derived classification methods using five-fold cross-validation.



\### Stage 9: Final Verification



Generate a prospective verification plan:



```bash

python stage9\_prepare.py

```



Run the final EnergyPlus simulations:



```bash

python stage9\_energyplus\_runner.py

```



Evaluate the frozen models:



```bash

python stage9\_evaluate.py

```



Important: These commands describe the original research workflow. Rerunning preparation scripts may overwrite existing artifacts. Back up the supplied results before reproduction.



The final holdout must not be used for model selection or tuning.



\## 10. Interactive Prediction Application



The research also developed an interactive surrogate prediction interface.



The application accepts five input parameters and provides:



\- Predicted thermal-risk class

\- Predicted operational Tmax

\- Calculated available cooling capacity



The application source code is not included in this repository release.



The trained models are provided for further application development.



\## 11. Limitations



\- The research considers one reference data-center model.

\- Singapore IWEC weather was used.

\- Synthetic heatwaves modify outdoor dry-bulb temperature while other EPW fields remain unchanged.

\- Cooling was represented using an Ideal Loads Air System.

\- The cooling-capacity derating factor was not calibrated to a specific HVAC system.

\- IT thermal shutdown behavior was not explicitly simulated.

\- The independent verification dataset contains only 20 cases.

\- Predictions near critical thermal-risk boundaries require additional verification.



The surrogate is intended for exploratory scenario screening rather than direct operational safety certification.
